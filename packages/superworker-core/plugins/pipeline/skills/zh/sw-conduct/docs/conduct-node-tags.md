# conduct 节点标签（tag）与 cycle 分流

> 本文件说明**节点 tag 与 cycle 分流**的设计依据：词表约定、过滤判据，以及为何过滤仅作用于选点阶段。
> 状态与推进契约见 [`./conduct-state.md`](./conduct-state.md)；派发链见 [`./conduct-dsh-dispatch.md`](./conduct-dsh-dispatch.md)；多条 cycle 并行时指令作用域的可见性规则，见状态契约中的上下文注入一节（指令仅分 `global` 与 `cycle` 两级）。
>
> 核心规则一句话：**节点可以不带 tag；cycle 的 `tags` 是该执行线的固定选材范围（全生命周期沿用）；过滤只作用于「挑选下一个节点」这一步。**

## 0. 设计动机

当同一张 DAG 同时包含文案、代码与美术三类任务时，若没有过滤机制，每条执行线的职责就会散落在各轮挑点结果里——用户无法声明「这条线只处理文案」或「这条线只改动代码」。

tag 机制用于表达这一边界：节点通过 tag 声明任务类别，cycle 通过过滤集声明选材范围。以 `--tags coding` 启动的 cycle，从第一个节点到最后一个节点始终使用同一份过滤集，只挑选代码类任务。

## 1. 推荐词表

约定三个基础词：`writing`（文案）、`coding`（代码）、`art`（图像/美术）。

词表是**面向人的约定**，引擎不作硬性拦截：使用词表外的 tag 会输出一行警告但照常接收——项目出现第四类工作时可直接写入，警告仅用于提醒已超出默认词表。过滤始终按字面精确匹配。

## 2. 存放位置与不对称设计

- **节点 tag 存入 DAG**：属于图的固有属性，与依赖边、节点状态一样由图自身描述。
- **cycle 过滤集存入 cycle 记录**：属于执行线的持久属性，随 cycle 生命周期保持不变。启动命令会**同时**将过滤集交给首次选点与 cycle 记录——因为首次选点发生在 cycle 创建之前，若仅写记录，首枚节点可能挑到其他类别的任务；后续每次选点均从该记录读取复用，杜绝中途漂移。
- **两侧刻意不对称**：节点 tag 为可选项，未设置时图中不写入该键（保证存量回归兼容）。**cycle 的 `tags` 为必填项**：它不仅决定选点过滤，还界定维护通道的适用领域，缺省会导致「哪条线响应维护度量」出现歧义。
- **权重仅计算一次**：节点评分仍在整个未完成子图上统一计算，过滤集只做行级筛选、不改变分数——因此「过滤集内第一名」与「全图排序」遵循完全一致的优先级。

## 3. 过滤判据

> 节点属于当前 cycle 的选材范围 ⇔ 该节点**没有任何 tag**，或其 tag 集合与 cycle 的过滤集**存在交集**。

- 节点可挂载多个 tag：例如 `art,writing` 同时归属两条执行线，先挑到它的一方生效。
- **无 tag 节点默认对所有范围可见**：这是保守策略。漏挡的代价只是多执行一个节点，而误挡会导致任务永远无人认领、直到人工排查才暴露。因此「无 tag」恒表示「不设限」。
- 仅在存量历史记录中出现未设过滤集的 cycle 时，整张图均为其选材范围。

## 4. 为何过滤仅作用于「挑选下一个节点」

过滤是一条**选点规则**，将其渗入其他阶段会引入额外复杂度与状态冲突：

- **不影响已在运行的节点**：cycle 认领节点后会写入持有记录，后续推进只认该持有记录。即便过滤集与之不匹配，已认领的节点仍照常跑完并收尾——中途推翻已认领节点会破坏状态一致性。
- **不改动依赖关系**：被 tag 过滤掉与前置依赖未满足是两回事。被过滤的节点不会变更状态、不会标为 `shelved`，依赖边保持原样——它只是「本轮不挑」，而非「节点异常」。

## 5. 跨线就绪时的停顿策略

本线过滤集内仍有就绪节点时照常挑选第一名；全图无就绪节点时照常停下；**本线无就绪节点、但图中有其他被 tag 挡住的就绪节点时——同样停下。**

此处停顿意在将决策权交还用户：本线任务已完成，另一类任务是否启动、何时启动应由人决定。工具能判断「本线无活、他线有活」，但无法判断「此刻是否应该开启第二条线」。

停顿时会生成面向用户的一句话 `reason`，点明哪些节点已就绪、被哪些 tag 拦截，并附上可直接复制执行的新建 cycle 命令；其他类别的任务原样留在图中，不加锁，也不标记失效。

## 6. `--node` 手动指定节点

用户通过 `--node` 显式点名的节点沿用既有语义：就绪则直接执行，未就绪则拒绝并说明原因。过滤集只约束自动选点，不应静默吞掉用户手敲的节点 ID。无论执行还是拒绝，若该节点不在本线过滤范围内，都必须明确提示「不在本线范围内」，避免用户误以为是依赖未满足。

## 7. 空过滤集（回归底线）

写入路径一律要求提供 `--tags`，空过滤集分支仅保留给**存量历史记录**中无 tag 的 cycle：

- 过滤集为空 ⇒ 整张图均为选材范围，选点结果、路径记录与数据结构与引入该特性前逐字节一致。
- 节点无 tag ⇒ 在任意过滤集下均可见，且图中不新增额外键。
