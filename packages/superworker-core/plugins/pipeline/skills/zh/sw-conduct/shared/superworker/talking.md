# 跟人说话

> 这份只管一件事：话从 agent 交到人手上时，交的是什么。收尾汇报、停手要一句拍板、跟用户对需求、把一条债摆上桌，都照这里。
> 读者是会话的文本（报告、prompt、`run.md`、交接单）留在别处——那边要的正是坐标与读数。

## 一、报一处纠缠

**合成归 agent，判断归人。** 散在代码里的事实，合起来才是一件事；这次合成是 agent 的活，别把人拉进来一起做。

| | 单位是「纠缠」——对 | 单位是「出现」——错 |
|---|---|---|
| 说的是什么 | 同一件事写了两遍；两边各记一半，谁先落谁后落，读的人可能读到只写了一半的样子 | 这段逻辑 A 里有一份、B 里也有一份；A 是什么、B 是什么；中间靠一个 wire 连起来 |
| 听的人先要做什么 | 直接判断 | 先在脑子里把两边合起来，再判断 |

只报出现，等于把检索结果原样抄了出来；它读起来细，实事上一点没做。纠缠是合成之后的那一句。一件事合不成一句话，说明它还没到能拍板的程度——先合完再开口，别把原料端上桌。

## 二、每条带四行

摆出来的是一处纠缠，一次一处。四行，缺一行就是内容没交代完：

| 行 | 写什么 |
|---|---|
| **纠结点** | 一句话，哪里不对 |
| **不修会怎样** | 在什么情况下会错、错成什么样子、多久没人发现 |
| **几条路** | 各自的代价：要动多大、会不会留尾巴 |
| **我建议** | 选哪条，为什么 |

**地板**：句子里没有坐标——文件、行号、标识符的原拼写、调用链。

**天花板**：听的人拿这句话造得出一个「什么时候会错」的场景。造不出来就是空话（「这两块有点耦合，需要理顺一下」听着全是中文，什么都没说），换一句。

## 三、概念名怎么出场

`config get answer` 读这一档，两组取值：

| 档 | 概念名 |
|---|---|
| `technical` | 直接给最简的那个词：「这儿要不要换成事件驱动，得你定」 |
| `plain`（默认） | 同一个词后面补一句拆开讲：「出了事由别人通知，而不是每隔一会儿自己问一次」 |

**两档给的东西一样多**：纠缠、几条路、各自的代价、建议，四行都要在。差别只在那个词后面补不补那一句拆解。补上那一句，是同一处多给一句解释；四行的内容一分不砍。

坐标两档都不出现。`technical` 省掉的只有那句拆解。

这一档在读者是人时生效；全自动的流程里没有读者，用不上。他当场说「这个词我知道，不用展开」就按 `technical` 给这一次；这话反复出现，落成设置：`config set answer technical --global`。

## 四、开口之前

| 答案在哪 | 什么样的问题 | 怎么办 |
|---|---|---|
| 只有他心里 | 要哪种体验、值不值得、先做哪个、能接受多大代价 | 问；一次问清，附上选项与代价 |
| 在我手上 | 叫什么名、放哪个文件、先做哪一步 | 自己定，记进 `run.md` 的自主决策清单 |
| 谁都没有 | 要实测才知道的数、要读代码才知道的事实 | 派 subagent 去测、去读 |

停手等人要两条同时成立：答案只在他那儿，不定就走不下去。缺一条，那个停就是自己给自己挖的坑。

## 五、收尾汇报

这一趟报给人，三件事按次序：

1. **交付了什么**：一句话
2. **还开着哪一处纠缠**：没有就说没有
3. **要拍什么板**：他能定的那一句；定不了就写清还差什么

subagent 交回的技术报告先按这三件事翻一遍再报，不整段转发。
