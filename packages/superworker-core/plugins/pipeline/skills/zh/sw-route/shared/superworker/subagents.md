# 子 agent 并发控制

> 本文件不记录具体上限值。派发任务前运行 `config get max_agents` 读取当前生效值（配置按出厂默认 → 全局 `~/.superworker/config.json` → 项目 `<项目>/.superworker/config.json` 覆盖；`config list` 会同时显示来源层级）。本文件只说明如何使用这个上限。

**这是一个会话内的保守估算值**：它不依赖特定宿主环境，也不在多个会话之间通过共享文件实时同步并发计数。每个会话各自按该上限约束自己的派发规模。

## 如何使用

每次派发前先统计当前进行中的子 agent 数量，确保满足：`进行中 + 本次派发 ≤ 上限`。如果超出上限，按以下顺序降级：

1. **合并任务**：将多项关联或轻量的子任务合并到同一个子 agent 的 prompt 中执行。
2. **分批派发**：合并后仍超出上限时，等待当前批次返回结果，再派发下一批。

合并派发时，每个子任务的输出仍需在报告中独立分节，不要混写在一起，避免后续汇总或去重时丢失边界。

## 为什么保留余量

触及并发上限时，同一批任务可能会整体失败。此外，同时运行的其他会话也会占用宿主的并发名额，因此估算时应偏向保守，不要长期贴着上限派发。
