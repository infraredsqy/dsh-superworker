# 压缩判据

> 供 scan subagent 使用，与 [`./garbage-patterns.md`](./garbage-patterns.md) 一同读取。本判据只看一件事：**该用例为快档实测耗时增加了多少**；是否验真东西归 `garbage-patterns.md` 管。

## 拖慢快档的判定

满足以下任一条即视为拖慢快档：

1. **位于快档且开销高**：启动真实子进程、访问非本地文件系统资源、等待真实时钟、加载模型、监听端口或发起网络请求。
2. **位于快档且命中项目自身的慢档标准**（如真实服务子进程、真实耗时等待、注入慢模型、单条实测超阈值等）。
3. **项目尚未分档**，但该用例在全量运行中明显拉长了整体耗时。

判据以**项目自身约定为准**。若项目已定义阈值（如「快档每轮 ≤10 秒」），按项目阈值判定；未定义时直接报告事实（该条耗时及占套件比例）。

## 拆分原则

单条测试常混杂两类断言：

- **纯逻辑 / 纯结构断言**：毫秒级，不依赖子进程、时钟或模型 → **提取到快档**。
- **依赖真实环境的部分**：留在慢档。

提取到快档的测试必须**完全自洽**：不依赖慢档遗留状态或共享 fixture 副作用，可在快档中独立运行。

> **拆分优于整条移档**：拆分可同时满足压缩与覆盖。扫描时先判断是否可拆，拆不动再整条移档。

## 移档方式

按项目机制选择：

- **标记机制**（如 `slow` 标签）：为慢用例或慢文件打标，由快档命令自动过滤。
- **独立入口**（如双命令或双目录 `tests/` 与 `bench/`）：将用例移至慢档入口，并同步更新构建/测试收集清单。

**项目尚未区分快慢档时，自行建立一套**：将无法压低的重用例（真实子进程、时钟等待、模型加载、端口监听）拆为独立慢档（通过标记或独立入口），同步更新构建与收集清单，建完后快慢两档各跑一次并报告实测耗时。

## 禁止事项

- **禁止以删除换时间**：慢但验证真实业务的测试必须移档或拆分，删除等于削减覆盖。
- **禁止将慢断言搬入快档凑数**：只有毫秒级纯逻辑断言可进入快档。

## 合并返回格式

与 `garbage-patterns.md` 合并为同一份 JSON，每条 finding 同时包含 `quality` 与 `compression` 两栏：

```json
{
  "file": "tests/test_example.mjs",
  "findings": [
    {
      "test_name": "仅监听 127.0.0.1",
      "quality": { "type": "hardcoded-count", "line_start": 15, "line_end": 22, "judgment": "partial" },
      "compression": {
        "slows_fast_lane": true,
        "reason": "启动真实服务子进程 + 等待真实时钟",
        "splittable": [
          { "what": "端口解析函数的纯逻辑断言", "lines": "31-38" }
        ],
        "action": "split"
      }
    }
  ]
}
```

- `quality.judgment`：`entire`（整段垃圾）/ `partial`（混合，仅删垃圾行）/ `none`（验真业务）
- `compression.action`：`move`（移出快档）/ `split`（可拆，快断言列在 `splittable`）/ `none`
- **删除与否由指挥者按动作表裁定**：仅当 `quality.judgment` 为 `entire` 或 `partial` **且**通过覆盖门槛时才删除。scan 只报事实，不写「建议删除」。
