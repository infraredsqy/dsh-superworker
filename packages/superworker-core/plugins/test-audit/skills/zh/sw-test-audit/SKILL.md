# sw-test-audit

> 所属插件：`test-audit`（随插件安装/卸载）。
> 调用方：用户（`/sw-test-audit`，直接跑到底）或指挥者（节点 `spec.md` 的 `method: ` 行点名，维护通道节点由此触发）。
> 职责：审计测试套件——删除无有效验证的测试，移出或拆分拖慢快档的测试，缺少快慢分档时自行建立。
> 是否派发 subagent：是，仅一层（scan / removal）；被派发的执行者若读到此文件，停手回报。

> **硬性约束（违反任一条即任务失败）**
> 1. **指挥者不读测试源码**：扫描必须派发 subagent，指挥者只处理结构化结果与高层上下文。
> 2. **自主裁定**：不产出待确认清单，不停下来询问用户（若调用时用户附带了额外限制，按限制收窄范围）。
> 3. **改动后必须验证**：编译通过 + 剩余测试通过，并报告实测耗时。

## 双判据与动作表

质量与压缩读同一批文件，一次扫描同时产出，不重复扫两遍：

- **质量**：是否验证了真实业务。判据见 [`./garbage-patterns.md`](./garbage-patterns.md)（垃圾模式、覆盖门槛与安全例外）。
- **压缩**：是否拖慢快档。判据见 [`./compression-criteria.md`](./compression-criteria.md)（拖慢判定、拆分与移档方式）。

动作由两项结论共同决定：

| | 有价值 | 无价值 |
|---|---|---|
| **拖慢快档** | 移出快档；可拆的快断言拆入快档 | 删除 |
| **不拖慢快档** | 保留 | 删除 |

- **删除必须通过覆盖门槛**：同时满足「命中垃圾模式」**且**「该业务在别处已有其他用例覆盖」时才允许删除——仅因耗时慢而删除等于削减覆盖。

## 入口与范围

| 调用方 | 范围来源 |
|---|---|
| 用户调用 `/sw-test-audit` | 调用时附带的说明；未指定则为整个测试套件 |
| 管线节点（`spec.md` 的 `method: ` 行点名） | `spec.md` 指定范围，不得自行扩至全库 |

管线节点的 `mode`（是否停顿或询问）由 `sw-conduct` 管理。

## 执行流程

所有管线命令均通过 `superworker` 工具调用（传 `word` 与 `args`，加 `help` 查看用法）。

### 1. 摸清测试结构

派发扫描前先掌握项目的测试组织、测试框架（Catch2 / Jest / pytest / node:test 等）、构建与验证命令，以及快慢档配置（`slow` 标记、双入口或并行开关）；信息不足时派 subagent 探查，指挥者自身不直接翻测试源码。

### 2. 派发扫描

scan subagent 数量按文件规模决定：默认 1 个覆盖全部，文件过多时再拆分。派发前按 `config get max_agents` 核对并发上限，超出则合并或分批。

每个 scan prompt 必须提供：

- [`./garbage-patterns.md`](./garbage-patterns.md) 与 [`./compression-criteria.md`](./compression-criteria.md) 的**绝对路径**
- 按当前项目测试框架翻译后的模式示例
- 待扫描文件清单
- 合并后的双判据返回格式

并行派发所有 scan subagent，等待系统唤醒通知，不轮询。

### 3. 汇总与裁定

按文件分组，为每条发现给出质量与压缩两项结论，按动作表落定处理方式；按 `entire` / `partial` / `move` / `split` 分类整理，逐条写明动作与理由。

### 4. 执行与验证

派发 removal subagent（默认 1 个，改动面极大时再拆）：

- **删除**：删除指定的测试用例或垃圾断言行；文件清空后从构建系统中移除。
- **移档**：按判据方式移出快档；项目无快慢分档且压不下去时，自行将重用例拆成独立慢档。
- **拆分**：提取纯逻辑快断言进快档，保留依赖真实环境的部分在慢档。

**验证要求**：确保编译通过且剩余测试通过（至少不新增失败）。命令与测试档位遵循 `sw-conduct/SKILL.md`「测试档与验证」一节；单独安装 `test-audit` 时，通过 `config get test_tier` 读取档位并按项目验证命令执行。**必须报告实测耗时**：快档耗时必报（压缩验收依据）；管线节点入口还须报全量耗时（维护通道节点的完成判定读取该值）。缺少实测读数等于未完成。

### 5. 收尾

汇报内容：删除条数（整段 N / 局部 M 处）、移档条数、拆分条数、清理空文件数、编译与测试结果、快档（及节点全量）实测耗时、未处理项（含被覆盖门槛拦下保留的条目）。

- **独立运行**：自行提交本轮改动的文件，不碰工作区内其他未提交改动。
- **管线节点入口**：不自行提交——关节点、提交推送与派发全部交回 `sw-conduct`，本技能只交回报告。

## 边界

| 场景 | 处理方式 |
|---|---|
| 调用时限定「只看不改」或其他限制 | 按指示收窄范围（如仅扫描并输出报告） |
| 验证失败 | 如实报告失败详情并停手，不猜、不回退、不硬凑 |
| 发现大规模测试重构需求 | 建议转 `/sw-route` 建节点进图 |
| 项目无测试 | 报告「未发现测试文件」并退出 |

**产物只进报告**：扫描结论不入库、不额外落盘；需留存原始输出时按约定目录存放（节点内用 `.superworker/nodes/<节点 uuid>/temp/`，项目内用 `.tmp/`）。
