# tests/ — The unit suite: what a test may pin, and what is walked by hand

> This file is a signpost, capped at 15 lines: one line per entry — only what this layer holds and when to read it.

**Pin behaviour and identity, leave the panel's wording alone.** The copy, the layout and the readings that need a real record move too often to hold; those are on the hand pass in [../docs/publish.md](../docs/publish.md).

- `client-*.test.mjs` — The browser half. The unit side runs the panel's own modules in Node: a cell's name and handles (`client-nodes`), what one write leaves on the note line (`client-outcome`), the external-store skeleton the ports stand on (`client-store`), the data plane's two roads and the argument shape each call reaches with (`client-data`), the workspace selector's candidates (`client-workspaces`), the config section's rows grown from readings (`client-config`), the settings pathway (`client-prefs`: the panel's values read out of a settings document, the write-back op carrying the right revision, a snapshot that keeps its identity, and `buildConfig` against the host field table), the weight gauge's judgment (`client-pool-gauge`), and the map's placement and camera (`client-map-layout`). The built-panel side runs the built `lib/client.js` (`npm test` builds it first; a file that needs it skips itself with the reason when it is not there): the shell boot is `helpers/`'s one copy — its spec-only face (`loadSpecOnly`) serves a file that wants the plugin's units without a mounted panel — and its files pin the shell getting its spec and the panel mounting (`client-render`, the map's touch road riding along in `client-map-gesture`), the overview's presses (`client-overview`), the two seats and the settings write held open (`client-mount`, `client-view`), the channel that makes the panel live (`client-remote-mount`, `client-remote-gateway`, and `client-apply-mount` — the case that fails when the asynchronous mount is not handled), and the gauge's drawn tips (`client-pool-gauge-draw`). What the drawing looks like is the hand pass's, not these files'
- `host-*.test.mjs` — The host half: the four sources, paging refusals, what each write lands in the record (and the engine's own sentence coming back), the session opener's flow, the dispatch relay — the claim a dispatch lands, the serial chain, the trigger behind the switch, and the button walking the same path (`host-relay`) — the package's plugin line, and the plugin skills placed into the DSH skill root, confirmed in a session's own catalog view, and taken back out (`host-skills`), and the injection of a workspace's instructions into the session's runtime context: the text byte-identical to the plugin's own listing, the four silences, the switch, a linked-worktree session carrying its main tree's reading, and a host with no prompt service (`host-instruction-context`), and the panel's one channel (`host-pump`, `host-gateway`): the first frame out before anything changes, the record directory and the session notices as the only wakes, an unchanged reading sending nothing, a refused read riding a frame that leaves the stream open, and the endpoint opened through the gateway's own stream carrier — the issue pool's weight table: a bad table answers `null` rather than zeros, and the walk landing at the installed layout's relative depth (`host-pool-weights`)
- `model-*.test.mjs` — The model layer: readings computed from the four records, one instant at a time, pure functions
- `helpers/` — The stand-ins the files share: the workspace-files port, the host context (services by name, every face a parameter), the agents registry the opener's creates are recorded on (the create gate, the wait ask and the tool recording are faces switched on, not copies), the git runner that lays a real worktree down, the settings document, the locale service, the slot roster, the skill catalog's two views and the one skill placement a case puts into a pinned home, npm's `files` matching, the built panel's boot and its spec-only face, the two waits (the negative one only disproves), a temp superworker project and the home switches' pinning — a per-file pin: the ad-hoc `--test-isolation=none` run shares one process, so a case reading its own pin back (the three diagnostic cases in `host-executor.test.mjs`, and the relay's in-flight one) skips itself there with the reason. One copy each; a file needing a narrower face turns faces off instead of copying the stand-in
- `package-surface.test.mjs` — The package face (`files`, exports, `engines`, the patch line, the `prepack` chain — its one copy lives in `package.json`) that publishing depends on: the artifact carries the two halves, the engine product and the data
- `engine-inline.test.mjs` — The engine package's way in: it is a workspace package of this repo, no build external names it, and an entry importing it lands in the bundle as code rather than as a package reference. Skips the two legs that need `packages/superworker-core/dist` with the reason when it is not built; `npm test` builds it first
