# tests/ — The unit suite: what a test may pin, and what is walked by hand

> This file is a signpost, capped at 15 lines: one line per entry — only what this layer holds and when to read it.

**Pin behaviour and identity, leave the panel's wording alone.** The copy, the layout and the readings that need a real record move too often to hold; those are on the hand pass in [../docs/publish.md](../docs/publish.md).

- `client-render.test.mjs` — The built `lib/client.js` over the in-memory port: the shell gets its spec, the panel mounts, every pane its tabs point at opens, the console stays clean — the map's touch road (`client-map-gesture.test.mjs`) rides on the same built panel and is that wiring's own file. Both skip themselves with the reason when the bundle is not built; `npm test` builds it first
- `overview-geom.test.mjs` / `client-overview.test.mjs` — The overview: the window boxes as numbers over stage tiers (nothing off the stage, nothing on the rail's lane), the finished window's check and the running ring as boxes on the same table, and the built panel's four motion marks — enter, leave (removed from the page after its span), fresh row, breathing border — each bound to its fact, plus the main window's three states, one fact each: running draws as it runs, not running under no gate is veiled under the check, at a person's gate it breathes amber with neither — while a child is drawn only while it runs, leaves by its own leave animation when it ends, and turns the ring
- `client-mount.test.mjs` / `client-view.test.mjs` — The two seats and the settings section: registration, the label function, unmount discipline, the language port; and the view the panel shows, over the built bundle with the settings write held open: a pick leads, an earlier write's echo cannot flash the stage back to the view the reader just left, and a fresh mount lands on the remembered view
- `host-*.test.mjs` — The host half: the four sources, paging refusals, what each write lands in the record (and the engine's own sentence coming back), the session opener's flow, the dispatch relay — the claim a dispatch lands, the serial chain, the trigger behind the switch, and the button walking the same path (`host-relay`) — the package's plugin line, and the plugin skills placed into the DSH skill root, confirmed in a session's own catalog view, and taken back out (`host-skills`), and the skills' own wording: description length, no fenced command menus, no restating `shared/` (`host-skill-wording`), and the lines the panel spells for the `instruction` verbs, its scope list kept against the plugin's own surface (`host-instruction-lines`), and the injection of a workspace's instructions into the session's runtime context: the text byte-identical to the plugin's own listing, the four silences, the switch, a linked-worktree session carrying its main tree's reading, and a host with no prompt service (`host-instruction-context`), and the panel's one channel (`host-pump`, `host-gateway`): the first frame out before anything changes, the record directory and the session notices as the only wakes, an unchanged reading sending nothing, a refused read riding a frame that leaves the stream open, and the endpoint opened through the gateway's own stream carrier
- `model-*.test.mjs` — The model layer: readings computed from the four records, one instant at a time, pure functions
- `helpers/` — The stand-ins the files share: the workspace-files port, the host context (services by name, every face a parameter), the settings document, the locale service, the slot roster, the skill catalog's two views and the one skill placement a case puts into a pinned home, npm's `files` matching, the built panel's boot, the two waits (the negative one only disproves), a temp superworker project and the home switches' pinning — a per-file pin: the ad-hoc `--test-isolation=none` run shares one process, so a case reading its own pin back (the three diagnostic cases in `host-executor.test.mjs`, and the relay's in-flight one) skips itself there with the reason. One copy each; a file needing a narrower face turns faces off instead of copying the stand-in
- `package-surface.test.mjs` — The package face (`files`, exports, `engines`, the patch line, the `prepack` chain — its one copy lives in `package.json`) that publishing depends on: the artifact carries the two halves, the engine product and the data
- `engine-inline.test.mjs` — The engine package's way in: it is a workspace package of this repo, no build external names it, and an entry importing it lands in the bundle as code rather than as a package reference. Skips the two legs that need `packages/superworker-core/dist` with the reason when it is not built; `npm test` builds it first
