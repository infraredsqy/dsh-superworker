# src/ — Host half, model layer, and browser half: records read in, readings computed, panel drawn

> This file is a signpost, capped at 15 lines: one line per entry — only what this layer holds and when to read it.

- `host/` — Host half: the plugin entry, the service for those record and note endpoints, the native opener of a node's work session and the writer of its session note (`executor.ts`), the dispatch relay: the one path every dispatch walks — the panel's button or the relay itself — and the trigger that opens the next leg after a session closes, on a switch (`relay.ts`), the lines the panel spells for the `instruction` verbs — the word and its five verbs belong to the shipped plugin, which imports nothing from the engine, so the four translations live here (`instruction-lines.ts`) —, the placement of the skills the shipped superworker plugins carry into the DSH skill root, and a session-side diagnostic read of them (`skills/`), the agent-facing `superworker` tool and the wake that offers it — registered once, into the registry's global layer, with one condition the registry asks every step: a `.superworker/` workspace (or a recognizable legacy record directory), a pipeline skill load, or a `/sw-*` claim (`tool.ts`, registered and gated by `wake.ts`), the injection of the constraints in force in a session's workspace into that session's runtime context — the text is the shipped plugin's own `instruction list`, an optional contribution with a switch (`instruction-context.ts`) —, the one channel the panel draws from: the reading pushed when the records change, woken by the record directory, the session notices and this half's own writes, never by a poll (`pump.ts`, exposed as the `watch` stream endpoint), the issue pool's weight table — the plugin's own declaration, read off the folder this package ships and handed in with every reading, `null` and never a set of zeros when it cannot be obtained (`pool-weights.ts`) —, boundary shapes, data fetching and writing, the settings schema, and the one file every reach into the host context is read through (`seams.ts`). A refusal travels as a code (`failure.ts`), never as a sentence. Read when changing data fetching, the session opener, the dispatch relay, the tool's registration, or boundary shapes
- `model/` — Model layer: the four records and the session-note shape (plus the pool's weight-table shape, on the one module the host half's compile face includes), plus one instant → the reading at that instant; pure functions, no data fetching, no DOM, and no file opened to find a weight — the pool reads by the table it is handed, and every weight is `null` when it was handed none. Read when changing how readings are computed or the record shapes
- `client/` — Browser half: the main panel, the settings section, the two mount points in the dispatch-center panel, the language layer (`words.ts` spells a fact, `locale.ts` attaches to DSH's own language service, `locales/` holds the lookup tables; a new language is a file beside `locales/zh.ts` with the same key set plus one line in `locales/index.ts`), the overview's windows (`overview.tsx` draws the reading over the layout in `overview-geom.ts`, with `session-events.ts` forwarding DSH's own session windows, and its node rail — one bar per step of the line, a press switching the stage to it), and the data seam's two roads (`data.ts`: the mounted namespace when there is one, the carrier layer under it) with the contribution that mounts the namespace (`remote-mount.ts`; without it the panel reads once and then never updates), and the weight gauge's own judgment: whether it is drawn at all, and with which two numbers, a fact about the reading rather than about the layout (`pool-gauge.ts`; a table or a line the reading does not have draws nothing). Read when changing the UI, adding a language, or touching how the panel reaches the host
