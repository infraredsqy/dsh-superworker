# 闸口：等一声批准

> 模板注：判定块假定场地已 `git init`（`git status --porcelain` 才能字面执行）；落点一律写在场地（排练工作区根）内。
> 模板用法：立线后由指挥者把本模板抄进 `.superworker/nodes/<本节点>/spec.md`，`<本节点>` 以实战 uuid 替换。

## 目标

把上游两格的交付清单汇总成一页，交到人面前，由人决定这条线继续往下走还是停下。这一格是本线唯一的人闸。

## 落点

- 唯一落点：项目根目录下的 `gate-summary.md`。
- 只写这一份文件。上游产物只读，不改。

## 输入

- 「快工：一张小抄」的产物：项目根的 `cheat-sheet.md`。
- 「慢工：三段小传」的产物：项目根的 `actors/` 下三份小传。

## 内容要求

1. 一节汇总表，两行：每行对应上游的一格，写它交付了哪些文件、每个文件各多少行。
2. 一节结论，一句话：这两格是否按其 spec 的完成判定通过。
3. 全文非空行不超过 20 行。

## 完成判定

在项目根跑：

```pwsh
$files = "cheat-sheet.md","actors/alice.md","actors/bob.md","actors/carol.md"
$files | ForEach-Object { "{0} exists={1} lines={2}" -f $_, (Test-Path $_), (Get-Content $_ -ErrorAction SilentlyContinue | Where-Object { $_ -ne "" }).Count }
Get-Content gate-summary.md | Select-String "cheat-sheet.md","alice.md","bob.md","carol.md" | Measure-Object | Select-Object -ExpandProperty Count   # 期望 >= 4
(Get-Content gate-summary.md | Where-Object { $_ -ne "" }).Count   # 期望 1..20
git status --porcelain                                            # 期望只列出 gate-summary.md
```

通过判据：四个输入文件都在且行数大于零；`gate-summary.md` 里四个文件名各出现至少一次；非空行数落在 1 到 20 之间；上游两格已各自交付，仓库里新增的只有 `gate-summary.md`。

## 收尾

本格 `mode=checkpoint`：交付完成后照常交接、关格、提交，然后这条线停在人闸等你一句「继续」。你的批准就是下一步的放行。
